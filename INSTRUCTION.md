# Инструкция по работе с ботом Hotline Service

## 1. Описание проекта

**Hotline Service Bot** — автоматизированная система для сервисной службы, разработанная на Python с использованием библиотеки `aiogram 3.x`. Бот предназначен для приема, обработки и ведения заявок на диагностику и ремонт станков с ЧПУ.

Ключевые возможности:

*   **Прием заявок от клиентов** через пошаговый диалог (FSM) из 4 шагов с возможностью прикрепления фото/видео.
*   **Распределение ролей**: Клиент, Инженер, Администратор.
*   **Прямой канал связи**: диалог между клиентом и инженером, взявшим заявку в работу.
*   **Оценка качества**: клиент может оценить работу инженера по шкале от 1 до 5 звёзд.
*   **Администрирование**: управление инженерами и администраторами, статистика и экспорт данных в CSV.
*   **Контроль таймаутов**: бот автоматически уведомляет администраторов о заявках, которые долго не были взяты в работу.
*   **Хранение данных**: вся информация о заявках и сотрудниках сохраняется в базе данных SQLite.
*   **Хранение медиаматериалов**: фото/видео/документы заявок автоматически скачиваются и сохраняются в папки `media/ticket_<номер>/`.

## 2. Роли пользователей

В системе предусмотрено три уровня доступа:

*   **Клиент** — любой пользователь Telegram, запустивший бота. Может создавать заявки, просматривать FAQ, историю своих заявок, общаться с инженером и оценивать выполненную работу.
*   **Инженер** — зарегистрированный администратором специалист. Может просматривать новые заявки, брать их в работу, общаться с клиентами, завершать и отменять заявки.
*   **Администратор** — пользователь с полными правами. Управляет списком инженеров и администраторов, получает статистику и экспортирует базу данных заявок, а также уведомляется о новых и просроченных заявках.

## 3. Инструкция для Клиента

### 3.1. Начало работы

1.  Найдите бота в Telegram и отправьте ему команду `/start`.
2.  Появится главное меню с кнопками:
    *   **`🛠 Оставить заявку на сервис ЧПУ`** — создание новой заявки.
    *   **`❓ Частые вопросы`** — справочная информация (график работы, перечень услуг, сайт).

Дополнительно доступны команды:
*   `/my_requests` — история ваших заявок (кнопка **`📋 Мои заявки`**, если она доступна).
*   `/help` — краткая справка по возможностям бота.
*   `/cancel` — отмена текущего диалога оформления заявки.

### 3.2. Создание заявки

1.  Нажмите кнопку **`🛠 Оставить заявку на сервис ЧПУ`**.
2.  Бот последовательно задаст 4 вопроса:
    *   **Шаг 1/4.** Опишите проблему и прикрепите фото/видео поломки одним сообщением.
    *   **Шаг 2/4.** Пришлите фото шильдика станка (табличка с моделью) или напишите бренд и модель вручную.
    *   **Шаг 3/4.** Укажите город и ИНН или название компании.
    *   **Шаг 4/4.** Поделитесь контактом — нажмите кнопку **`📞 Поделиться контактом`** или введите контакт вручную.
3.  В любой момент вы можете прервать оформление, нажав кнопку **`❌ Отмена`**.
4.  После завершения заявка будет создана и отправлена всем активным инженерам, а также администраторам.

### 3.3. Общение с инженером

*   Как только инженер возьмёт вашу заявку в работу, вы получите уведомление.
*   С этого момента вы можете вести диалог прямо в чате с ботом: отправлять текстовые сообщения, фотографии и документы. Они будут мгновенно доставлены вашему инженеру.

### 3.4. Управление активной заявкой

Когда у вас есть активная заявка, в меню появляется кнопка **`❌ Отменить / Закрыть заявку`**. Она позволяет отменить активную заявку. Клиент и назначенный инженер получат соответствующее уведомление.

### 3.5. Оценка работы

После завершения заявки инженером бот предложит оценить качество обслуживания по шкале от 1 до 5 звёзд. При желании можно оставить текстовый комментарий, а затем нажать `/cancel` для завершения.

## 4. Инструкция для Инженера

Чтобы стать инженером, администратор должен добавить ваш Telegram ID в систему командой `/add_eng`.

### 4.1. Начало работы

После команды `/start` вы увидите меню инженера:
*   **`📋 Мои заявки в работе`** — список заявок, закреплённых за вами.
*   **`📥 Нераспределенные заявки`** — список новых заявок, ожидающих инженера.

Команда `/help` покажет краткую справку по меню инженера.

### 4.2. Приём заявки

*   Когда клиент создаёт новую заявку, вы получаете уведомление с полной информацией и кнопкой **`✅ Взять в работу`**.
*   Нажав её, вы закрепляете заявку за собой. Клиент получит уведомление о том, что вы подключились. Заявка становится вашей активной заявкой.

### 4.3. Общение с клиентом

*   После взятия заявки все ваши сообщения (текст, фото, документы), отправленные в чат с ботом, автоматически пересылаются клиенту.
*   **Если у вас несколько активных заявок**, бот предложит выбрать, какому клиенту вы хотите ответить. Используйте команду `/my_tickets` для переключения активной заявки.

### 4.4. Управление заявкой

Для активной заявки доступны кнопки:
*   **`✅ Завершить текущую`** — закрыть выбранную заявку как выполненную (без запроса комментария). Клиент получит уведомление и сможет оценить работу.
*   **`🚫 Отменить текущую`** — отменить выбранную заявку. Клиент получит уведомление об отмене.

Также в сообщении заявки доступны inline-кнопки **`✅ Завершить (Завершена)`** и **`🚫 Отменить заявку`**.

## 5. Инструкция для Администратора

Администратор получает права двумя способами: через переменную `ADMIN_IDS` в файле `.env` (базовые администраторы) или через команды `/add_admin` / `/del_admin` (администраторы, хранящиеся в базе данных). Все администраторы имеют одинаковые привилегии.

### 5.1. Узнать свой Telegram ID

Самый простой способ — написать боту `@userinfobot` в Telegram, и он пришлёт ваш ID.

### 5.2. Назначение администратора

*   **Через `.env`** (базовый администратор):
    1.  Откройте файл `.env` в корневой папке проекта.
    2.  Найдите переменную `ADMIN_IDS` и добавьте ID через запятую без пробелов. Пример: `ADMIN_IDS=7039700975,123456789`.
    3.  Сохраните файл и **полностью перезапустите бота** (например, через `start.bat`).
*   **Через бота** (дополнительные администраторы):
    *   Команда `/add_admin <ID>` — добавить пользователя в администраторы.
    *   Команда `/del_admin <ID>` — удалить пользователя из администраторов (нельзя удалить администратора, заданного в `.env`).
    *   Команда `/list_admin` — показать список всех администраторов (из `.env` и из базы данных).

### 5.3. Админ-панель

Команда `/admin` открывает админ-панель с inline-кнопками:
*   **`📊 Статистика`** — статистика по заявкам.
*   **`📥 Экспорт CSV`** — выгрузка заявок.
*   **`👥 Список инженеров`** — список инженеров.
*   **`👑 Список админов`** — список администраторов.

### 5.4. Управление инженерами

*   **Добавить инженера** — `/add_eng <ID> <Имя>`:
    ```
    /add_eng 123456789 Иван Петров
    ```
    Нельзя добавить инженера, который уже указан в `ADMIN_IDS`.
*   **Удалить инженера** — `/del_eng <ID>`:
    ```
    /del_eng 123456789
    ```
*   **Список инженеров** — `/list_eng`.

### 5.5. Статистика и экспорт данных

*   **Статистика** — команда `/stats` выводит:
    *   общее количество заявок, открытых, в работе и закрытых;
    *   статистику по инженерам (в работе / закрыто);
    *   среднее время решения заявки;
    *   среднюю оценку клиентов;
    *   статистику по городам/компаниям.
*   **Экспорт заявок** — команда `/export` формирует и присылает файл `tickets_report.csv` со всеми заявками.
    *   Поддерживается экспорт за период: `/export ГГГГ-ММ-ДД ГГГГ-ММ-ДД`.
        ```
        /export 2026-01-01 2026-01-31
        ```
    *   Файл содержит полную информацию, включая комментарии к закрытию.

### 5.6. Уведомления администраторов

Администраторы автоматически получают:
*   уведомление о каждой новой заявке;
*   уведомление о заявках, которые не были взяты в работу в течение заданного таймаута (`TICKET_TIMEOUT` в `.env`, по умолчанию 300 секунд);
*   сообщения о критических ошибках бота.

## 6. Техническая часть (для разработчиков)

### 6.1. Требования

*   Python 3.10+
*   Зависимости, перечисленные в файле `requirements.txt`. Основные: `aiogram==3.x`, `aiosqlite`, `python-dotenv`.

### 6.2. Настройка окружения

1.  Клонируйте репозиторий.
2.  В корневой папке проекта создайте файл `.env` (или `.env.txt`) по аналогии с `.env.example`.
3.  Заполните файл `.env` необходимыми данными:
    ```env
    # Токен вашего бота, полученный от @BotFather
    BOT_TOKEN=ВАШ_ТОКЕН_БОТА

    # Список Telegram ID администраторов через запятую
    ADMIN_IDS=7039700975

    # Путь к файлу базы данных SQLite
    DB_PATH=hotline_service.db

    # Таймаут (в секундах), после которого заявка считается просроченной
    TICKET_TIMEOUT=300

    # Каталог для сохранения фото/видео материалов (подпапки создаются по номеру заявки)
    MEDIA_DIR=media

    # Опционально: URL Redis для хранения FSM-состояний (если не задан — используется память)
    REDIS_URL=

    # Опционально: webhook-режим (если задан WEBHOOK_URL — бот работает через webhook вместо поллинга)
    WEBHOOK_URL=
    WEBHOOK_PATH=/webhook
    WEBHOOK_HOST=0.0.0.0
    WEBHOOK_PORT=8080
    ```
    > **Важно:** не храните реальный `BOT_TOKEN` в открытом виде в репозитории. Используйте секреты или не коммитьте файл `.env`.

### 6.3. Запуск

*   **Для Windows**: просто запустите файл `start.bat`. Он автоматически создаст виртуальное окружение (если его нет), установит зависимости и запустит бота.
*   **Для Linux/macOS (или вручную)**:
    ```bash
    # Создайте и активируйте виртуальное окружение
    python3 -m venv .venv
    source .venv/bin/activate

    # Установите зависимости
    pip install -r requirements.txt

    # Запустите бота
    python3 -m bot.main
    ```

### 6.4. Режимы работы

*   **Поллинг (по умолчанию)**: если `WEBHOOK_URL` не задан, бот использует поллинг через `dp.start_polling()`.
*   **Webhook**: если задан `WEBHOOK_URL`, бот запускает aiohttp-сервер и работает через webhook. Требуется настройка `WEBHOOK_PATH`, `WEBHOOK_HOST`, `WEBHOOK_PORT`.
*   **FSM-хранилище**: если задан `REDIS_URL`, для FSM используется `RedisStorage`, иначе — `MemoryStorage`.

### 6.5. Важные замечания

*   **Конфликт `getUpdates`**: лог-сообщение `TelegramConflictError: terminated by other getUpdates request` означает, что вы пытаетесь запустить вторую копию бота с тем же токеном. Убедитесь, что работает только один экземпляр.
*   **База данных**: файл SQLite (по умолчанию `hotline_service.db`) создаётся автоматически при первом запуске в директории, указанной в `DB_PATH`. Миграции применяются автоматически.
*   **Медиафайлы**: фото/видео проблемы и файлы переписки сохраняются в папку `media/ticket_<id>/` с порядковыми номерами (например, `001_photo.jpg`). Путь к каждому файлу фиксируется в таблице `media` базы данных. В Docker папка `media` монтируется как volume.
*   **Логирование**: логи пишутся в консоль и в файл `bot.log` (с ротацией по 5 МБ, хранится 3 файла).
*   **Права доступа**: проверка прав администратора выполняется как через переменную `ADMIN_IDS`, так и через базу данных (`is_admin`).

## 7. Интеграция с Битрикс24 (создание задач)

Бот умеет автоматически создавать **задачу** в Битрикс24 (не лид и не сделку) при взятии заявки инженером в работу. Задача назначается на пользователя Битрикс24, соответствующего инженеру.

### 7.1. Настройка

1.  **Получите URL входящего вебхука** Битрикс24:
    *   Зайдите в Битрикс24 → **Приложения** → **Входящие вебхуки** → **Добавить вебхук**.
    *   Выберите права на метод `tasks` (задачи).
    *   Скопируйте URL вида: `https://ваш_портал.bitrix24.ru/rest/1/ВАШ_ТОКЕН/`.

2.  **Добавьте переменные в `.env`** (см. `.env.example`):
    ```env
    # URL входящего вебхука Битрикс24
    BITRIX_WEBHOOK_URL=https://crm.wattsan.ru/rest/14/ВАШ_ТОКЕН/

    # (необязательно) ID пользователя, от чьего имени создаются задачи
    BITRIX_CREATED_BY=

    # Приоритет задач: 1-низкий, 2-средний, 3-высокий, 4-срочный
    BITRIX_TASK_PRIORITY=2

    # Дедлайн задачи в часах от момента взятия (пусто — без дедлайна)
    BITRIX_TASK_DEADLINE_HOURS=

    # ID папки на диске Битрикс24 для загрузки файлов (пусто — используется общий диск)
    BITRIX_DISK_FOLDER_ID=

    # Прикреплять ли файлы заявки к задаче (1 - да, 0 - нет)
    BITRIX_ATTACH_FILES=1
    ```

3.  **Сопоставьте инженеров бота с пользователями Битрикс24.**

    У каждого инженера бота должен быть указан `bitrix_user_id` — ID пользователя Битрикс24, на которого создаются задачи. Для этого администратор выполняет команду:
    ```
    /set_bitrix <ID_инженера_Telegram> <ID_пользователя_Битрикс24>
    ```
    Пример:
    ```
    /set_bitrix 123456789 14
    ```
    > **Как узнать ID пользователя Битрикс24?** Откройте карточку пользователя в Битрикс24 — ID виден в URL (например, `/company/personal/user/14/` — ID = 14).

### 7.2. Как работает

1.  Клиент создаёт заявку в боте.
2.  Инженер нажимает **«✅ Взять в работу»**.
3.  Бот создаёт **задачу** в Битрикс24:
    *   **Заголовок:** `Заявка #<номер>: <проблема>`
    *   **Описание:** компания/город, станок, проблема, контакты, клиент.
    *   **Ответственный:** пользователь Битрикс24, сопоставленный с инженером (`bitrix_user_id`).
    *   **Приоритет и дедлайн** — из переменных окружения (опционально).
    *   **Файлы заявки** (фото/видео/документы) — автоматически загружаются на диск Битрикс24 и прикрепляются к задаче (если `BITRIX_ATTACH_FILES=1`). Файлы загружаются в папку `BITRIX_DISK_FOLDER_ID` или в общий диск, если папка не задана.
4.  Если задача создана успешно — в логах появится запись; при ошибке или отсутствии сопоставления — бот продолжит работу, а ошибка попадёт в лог (интеграция не блокирует взятие заявки).

### 7.3. Примечания

*   Если для инженера не задан `bitrix_user_id`, задача **не** создаётся (в лог пишется предупреждение).
*   Если `BITRIX_WEBHOOK_URL` не задан — интеграция полностью отключена, бот работает как раньше.
*   Задача создаётся **только** при взятии заявки инженером (не при создании заявки клиентом).
*   Метод REST API: `tasks.task.add`.
