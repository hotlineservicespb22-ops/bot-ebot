# 🔧 Hotline Service Bot

Telegram-бот для сервисной службы по диагностике и ремонту станков с ЧПУ.
Принимает заявки от клиентов, распределяет между инженерами, ведёт диалог
клиент ↔ инженер, собирает оценки, даёт админ-панель со статистикой и экспортом.

## 🚀 Быстрый старт

```bash
# 1. Клонировать репозиторий
git clone git@hotline-bot:hotlineservicespb22-ops/bot-ebot.git
cd bot-ebot

# 2. Скопировать и заполнить .env
cp .env.example .env
# Отредактировать .env: BOT_TOKEN, ADMIN_IDS

# 3. Запустить через Docker
./manage.sh start
```

Без Docker:
```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python3 -m bot.main
```

## 🔄 FSM-воронка клиента (4 шага)

```
/start → [■■□□] Шаг 1: Описание проблемы + фото/видео
              ↓
         [■■■□] Шаг 2: Фото шильдика / бренд / модель
              ↓
         [■■■■] Шаг 3: Город + ИНН / компания
              ↓
              ✅ Шаг 4: Контакт (request_contact)
              ↓
         Заявка создана → уведомление инженерам
```

Таймаут FSM: 30 минут. Кулдаун между заявками: 60 секунд.

## 👥 Роли пользователей

| Роль | Возможности |
|------|-------------|
| **Клиент** | Создание заявок, просмотр FAQ, история, общение с инженером, оценка |
| **Инженер** | Взятие заявок, общение с клиентом, завершение/отмена заявок |
| **Администратор** | Управление инженерами, статистика, CSV-экспорт, дашборд |

## 🗄 Модель данных

| Таблица | Описание |
|---------|----------|
| `tickets` | Заявки (uuid, статус, инженер, клиент, описание) |
| `engineers` | Инженеры (ID, имя, активность, bitrix_user_id) |
| `admins` | Администраторы |
| `messages` | История переписки по заявкам |
| `ratings` | Оценки клиентов (1-5 звёзд) |
| `media` | Сохранённые файлы заявок |
| `ticket_notifications` | Уведомления инженерам |
| `ticket_escalations` | Дедупликация уведомлений о просрочке |

## 🔐 Безопасность

- **UUID заявок** — предотвращает перебор ID
- **SanitizingFilter** — маскирует токены в логах
- **XSS-защита** — экранирование HTML в дашборде
- **Whitelist расширений** — защита от загрузки исполняемых файлов
- **Webhook-аутентификация** — проверка X-Telegram-Bot-Api-Secret-Token
- **Rate-limiting** — кулдаун создания заявок, троттлинг callback'ов
- **Cascade delete** — автоочистка связанных данных при удалении заявки

### Healthcheck
Бот пишет heartbeat в файл `.heartbeat` каждые 5 секунд.
Watchdog (`watchdog.sh`) перезапускает контейнер при зависании >120 сек.

## 🔗 Интеграции

- **Telegram Bot API** — aiogram 3.x
- **Битрикс24** — создание задач при взятии заявки, загрузка файлов, уведомления в чат
- **Redis** — опциональное FSM-хранилище (без него — MemoryStorage)

## 📋 Переменные окружения

См. `.env.example` с подробными комментариями. Ключевые:

| Переменная | Назначение |
|------------|------------|
| `BOT_TOKEN` | Токен бота Telegram |
| `ADMIN_IDS` | ID администраторов через запятую |
| `REDIS_URL` | URL Redis для FSM (опционально) |
| `WEBHOOK_URL` | URL для webhook-режима |
| `WEBHOOK_SECRET_TOKEN` | Секретный токен webhook |
| `BITRIX_WEBHOOK_URL` | Webhook Битрикс24 |

## 📈 Дашборд
